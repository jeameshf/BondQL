## 1. 系统概述

BondQL 是一款基于大语言模型的**智能问数系统**。用户通过自然语言提问，系统自动将问题转换为 SQL、在真实数据库上执行，并以**图表 + 数据表 + 智能分析**的形式返回结果。
<img width="1920" height="860" alt="829d0b2e00a50da3e3e0fe8fb2ef6f3f" src="https://github.com/user-attachments/assets/0a8de1c7-e831-4603-b4f0-1f242fca8563" />


### 1.1 核心能力

| 能力           | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| 自然语言转 SQL | 对接大模型（DeepSeek / OpenAI / Ollama 等），自动生成 SQL    |
| 真实执行 SQL   | 支持 SQLite / MySQL / PostgreSQL / Oracle，真实连接、真实查询 |
| 可视化图表     | 柱状图 / 折线图 / 饼图 / 排行图，可切换、可导出 CSV          |
| 智能分析       | 自动生成总量、均值、占比、环比等数据洞察                     |
| 数据源管理     | 连接数据库、连通性测试、自动同步表结构                       |
| 表关联建模     | 拖拽式画布，字段连线定义 JOIN 关系                           |
| 业务上下文     | 术语词典、SQL 示例库、自定义提示词                           |
| 权限管控       | 登录鉴权、角色权限、数据源/表/列级权限规则                   |
| 多工作空间     | 资源隔离，工作空间可绑定数据源与表                           |

### 1.2 技术架构

- **后端**：Python 标准库（http.server + sqlite3），零第三方运行依赖（数据库驱动已内置打包）
- **前端**：原生 HTML / CSS / JavaScript，无框架
- **元数据存储**：SQLite 单文件（`data/bondql.db`）
- **内置演示数据**：一套 CRM 数据（部门 / 销售 / 客户 / 产品 / 订单），开箱即可体验

## 2. 安装与启动

### 2.1 环境要求

| 项目     | 要求                                |
| -------- | ----------------------------------- |
| 操作系统 | Windows / Linux / macOS             |
| Python   | 3.8 及以上（推荐 3.10+）            |
| 浏览器   | Chrome / Edge 等现代浏览器          |
| 网络     | 接入大模型 API 时需要能访问对应接口 |

> 项目已内置数据库驱动（`libs/` 目录），**无需 pip install**。其中 MySQL / PostgreSQL 为纯 Python 源码，跨平台通用；Oracle 驱动为编译型，已按当前平台打包（换机器/换 Python 版本需重新获取对应平台的 oracledb wheel）。

### 2.2 启动步骤

```bash
# 进入项目目录
cd C:\work\BondQL

# 启动服务（默认端口 8000）
python server.py 8000
```

启动成功后控制台输出：

```
BondQL · 智能问数 已启动
访问地址:  http://127.0.0.1:8000
```

### 2.3 访问系统

浏览器打开 **http://127.0.0.1:8000**，进入登录页。

### 2.4 停止服务

在运行服务的命令行窗口按 `Ctrl + C` 即可停止。

### 2.5 项目目录结构

```
BondQL/
├── server.py          后端服务（API + 问数引擎 + SQL 执行）
├── web/               前端（index.html + app.js）
├── data/bondql.db     元数据与演示数据库
└── libs/              内置数据库驱动
```

## 5. 问数工作台

### 5.1 智能问数

智能问数是系统的核心功能。

**提问前**，在输入框上方选择：

1. **工作空间**（显示当前空间）
2. **数据源**（下拉，只列出当前工作空间绑定的数据源）
3. **模型**（下拉，选择用哪个大模型生成 SQL；未配置 Key 的模型会提示降级）

**提问方式**：

- 在输入框直接输入问题，回车或点击「发送」
- 或点击推荐问题（推荐问题由大模型根据表结构自动生成）

**示例问题**（演示数据源）：

- 「华南大区本月销售业绩是多少？」
- 「近12个月销售额趋势」
- 「各产品线销量占比」
- 「销售人员业绩排名 TOP10」
- 「销售额大于 500 万的区域有哪些」

**返回结果包含**：

- **执行步骤**：解析语义 → 匹配表关系 → 生成 SQL → 执行完成
- **图表**：柱状图 / 折线图 / 饼图 / 排行，可点击切换
- **数据表**：查询明细
- **智能数据分析**：总量、均值、最高/最低、占比、环比等洞察
- **继续追问**：推荐相关问题，点击即可追问
- **导出**：导出为 CSV 文件

**右侧「查询依据」面板**展示：

- 匹配术语、数据源、关联路径、SQL 示例
- 生成 SQL（语法高亮）
- 提示词约束
- 权限校验（行权限 / 列权限）

> **说明**：选择**演示数据源（CordysCRM）**且未配置大模型时，系统使用内置规则引擎直接回答；选择**真实数据源**（MySQL / PostgreSQL / Oracle）时，需配置可用大模型，由大模型根据真实表结构生成 SQL。

### 5.2 仪表板

将问数结果沉淀为监控视图。当前为演示数据，可查看各仪表板的 PV / 分享 / 刷新频率等。

### 5.3 问数历史

- 查看历史会话（标题、数据源、消息数、最后活动时间）
- **恢复**：重新打开该会话继续对话
- **删除**：删除单个会话
- **清空历史**：删除全部会话

## 6. 数据管理

### 6.1 数据源管理

数据源是问数的数据来源，**全局管理**（不绑定工作空间）。

**新建 / 编辑数据源**：点击「＋ 新建数据源」或卡片上的「编辑」，填写：

| 字段          | 说明                                    |
| ------------- | --------------------------------------- |
| 数据源名称    | 必填                                    |
| 数据库类型    | SQLite / MySQL / PostgreSQL / Oracle 等 |
| 主机名 / 端口 | 数据库地址                              |
| 数据库名      | 库名（SQLite 为文件路径）               |
| Schema        | 已取消，可忽略                          |
| 用户名 / 密码 | 连接凭据                                |
| 描述          | 用途说明                                |

**连通性测试**：点击卡片「测试连接」或弹窗内「测试连接」：

- 真实连接校验，**错误密码/地址会如实报错**，不再有“模拟成功”
- SQLite：真实打开文件并查询
- MySQL / PostgreSQL / Oracle：真实驱动连接

**其他操作**：

- 「设为问数数据源」：设为当前问数使用的数据源
- 「开启/关闭问数」：控制该数据源是否可用于问数
- 「删除」：删除数据源

### 6.2 表管理

- 顶部选择**数据源**，展示该数据源下的表
- 可为每张表填写**业务名称**与**描述**，勾选**启用/禁用**
- 点击「🔄 同步表结构」：真实连接数据库，自动读取真实表与字段（覆盖手动配置）
- 点击「编辑字段」：为每个字段填写**业务含义**与**描述注解**（帮助大模型理解字段）

### 6.3 表关联关系（拖拽式画布）

以可视化方式定义表之间的 JOIN 关系。

**操作步骤**：

1. 选择**数据源**
2. 从「表格库」把表**拖入画布**（或点击加入）
3. 在画布中**拖动表卡片**调整位置
4. **点击一个字段，再点击另一张表的字段**，即可连线建立关联
5. 点表头 ✕ 可把表移出画布
6. 点击「💾 保存关联」一次性持久化

- 下方「待保存的关联（草稿）」列表可删除单条
- 「重置」恢复为已保存状态
- 关联类型：1:N / 1:1 / N:M / 自关联

## 7. 业务上下文配置

### 7.1 术语配置

建立业务术语与数据库字段的翻译词典，消除大模型歧义。

- 每个术语包含：**术语**、**同义词**、**描述/计算逻辑**、**数据源**、**状态**
- 示例：「销售额」→ 必须使用 `actual_amount` 字段
- 支持搜索、新增、编辑、删除

### 7.2 SQL 示例库

针对高频、复杂查询，预先录入**标准问题**与**标准答案 SQL**。

- 查看示例的标准 SQL（高亮显示）
- 新增 / 编辑 / 删除示例
- 「在问数中执行」：直接以该示例的问题发起问数
- 规则引擎命中时会显示匹配到的示例

### 7.3 自定义提示词

定义适用于所有查询的通用规则。

- 每个提示词可**关联数据源**（下拉选择「全局」或具体数据源）
- 提示词内容会在问数时**注入大模型的 SQL 生成上下文**，约束生成结果
- 依据面板会展示该数据源生效的提示词约束

**示例提示词**：

```
# 全局规则
- 销售额必须使用 actual_amount 字段，不能使用 order_amount
- 日期查询默认最近 30 天，除非用户明确指定时间范围
- 排除状态为"已取消"的订单
```

## 8. 权限管理

### 8.1 权限配置

通过规则组设置**行权限**与**列权限**，实现数据隔离。

**新建 / 编辑规则组**：

- 填写规则组名称
- 添加一条或多条规则，每条规则结构化选择：
  - **权限类型**：行权限 / 列权限
  - **数据源**：下拉选择
  - **表**：下拉选择（联动该数据源的表）
  - 行权限 → 填写**筛选条件**（如 `region = '华东'`）
  - 列权限 → 勾选要**隐藏的列**

### 8.2 工作空间

工作空间是资源隔离与权限管理的基本单元。

**新建 / 编辑工作空间**：

- 空间名称、成员数、描述
- **选择数据源**：勾选归属该空间的数据源
- **选择数据表**：勾选该数据源下的表

工作空间卡片显示其绑定的数据源与表标签，可「切换到此空间」「编辑」「删除」。

## 9. 系统管理

### 9.1 MCP 服务

通过 Model Context Protocol 让第三方平台调用问数能力。

- 展示服务地址、传输方式（SSE / Streamable HTTP）、认证方式（JWT）
- 工具清单：`mcp_start`、`mcp_question`、`mcp_ws_list`、`mcp_datasource_list`
- 已集成平台：Dify、MaxKB、n8n、DataEase、Coze

### 9.2 小助手应用

通过嵌入式小助手把问数能力嵌入第三方系统。

- 基础应用（免后端对接）、高级应用（需登录）
- 「获取嵌入代码」复制嵌入片段
- 可启用 / 停用 / 配置

### 9.3 AI 模型配置

配置大语言模型，系统用大模型把自然语言转为 SQL。

**添加 / 编辑模型**：

| 字段     | 说明                                                 |
| -------- | ---------------------------------------------------- |
| 模型名称 | 自定义显示名                                         |
| 供应商   | DeepSeek / OpenAI / Ollama 等                        |
| 模型 ID  | 如 `deepseek-chat`、`gpt-4o`、`qwen2.5:7b`           |
| Base URL | 接口地址（DeepSeek 默认 `https://api.deepseek.com`） |
| API Key  | 模型密钥（已配置后留空保持不变）                     |

- **测试**：校验模型连接是否可用
- **设为默认**：问数默认使用该模型
- 未配置任何 Key 时，系统使用内置规则引擎（演示数据源可用）

### 9.4 系统设置

展示 MCP 服务配置、嵌入配置、外观设置、关于（版本、公众号、微信）。

## 10. 大模型接入指南

### 10.1 DeepSeek（推荐）

1. 进入「系统管理 → AI模型配置」
2. 编辑「DeepSeek-V3」模型（或新增）
3. 填写：
   - 模型 ID：`deepseek-chat`
   - Base URL：`https://api.deepseek.com`
   - API Key：你的 DeepSeek Key
4. 点击「测试」，提示「连接正常」即可
5. 「设为默认」

### 10.2 OpenAI

- Base URL：`https://api.openai.com/v1`
- 模型 ID：`gpt-4o`、`gpt-4o-mini` 等

### 10.3 本地 Ollama（免费）

1. 本机安装并启动 Ollama
2. Base URL：`http://127.0.0.1:11434/v1`
3. 模型 ID：`qwen2.5:7b` 等本地模型名
4. API Key 可留空（或任意值）

> 接入大模型后，问数走「大模型生成 SQL」；同时「推荐提问」「智能数据分析总结」也会由大模型生成。

## 11. 数据库连接指南

### 11.1 内置演示库（SQLite）

- 数据源 `CordysCRM` 指向内置演示库 `data/bondql.db`
- 包含 CRM 业务数据，开箱即可问数，无需任何配置

### 11.2 连接 MySQL

1. 「数据源管理 → 新建数据源」，类型选 MySQL
2. 填写主机名、端口（默认 3306）、数据库名、用户名、密码
3. 点击「测试连接」验证
4. 到「表管理」点击「同步表结构」读取真实表

### 11.3 连接 PostgreSQL

- 类型选 PostgreSQL，端口默认 5432，其余同上

### 11.4 连接 Oracle

- 类型选 Oracle，端口默认 1521，数据库名填 Service Name
- Oracle 不支持 `LIMIT`，系统已自动适配 `FETCH FIRST`

### 11.5 提示

- 连接真实数据库后，务必先在「表管理」**同步表结构**，让大模型知道有哪些表和字段
- 建议为关键字段补充**业务含义注解**，可显著提升 SQL 生成准确率

## 12. 常见问题 FAQ

**Q1：错误密码也能测试连接成功？**
不会。系统是真实连接校验，错误密码/地址会如实报错。

**Q2：选择了数据源但提问还是查的演示库？**
请确认聊天输入框上方的「数据源」下拉已选为目标数据源。切换工作空间后数据源会自动切换。

**Q3：Oracle 提问报 ORA-03049（LIMIT 语法错误）？**
已修复：系统对 Oracle 自动使用 `FETCH FIRST n ROWS ONLY`，无需手动处理。

**Q4：真实数据源提问报「请配置大模型」？**
真实库（MySQL/PostgreSQL/Oracle）需要大模型把自然语言转 SQL。请在「AI模型配置」配好可用的 API Key。

**Q5：大模型生成的 SQL 不准？**

- 在「表管理」为表和字段补充业务含义注解
- 在「术语配置」补充业务术语
- 在「自定义提示词」补充该数据源的规则约束
- 在「SQL示例库」录入高频问题的标准 SQL

**Q6：改了代码/配置不生效？**
后端代码改动需重启 `server.py`；前端改动刷新浏览器即可；数据库驱动新增后需重启。

**Q7：普通用户看不到数据管理菜单？**
普通用户默认只有问数工作台，管理功能仅管理员可见。

**Q8：端口被占用？**
启动命令改用其它端口，例如 `python server.py 8001`。
